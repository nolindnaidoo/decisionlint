# Contributing

[AGENTS.md](AGENTS.md) is the engineering standard for this repository: the
architecture, the invariants, the toolchain and the release. Read it before
writing code. This page says how to get a change in, and points there for
everything else rather than repeating it.

## Set up

Install Bun at the version CI pins, which is the one `bun.lock` was written
with (see "CI pins Bun" under Automation in AGENTS.md), then:

```bash
bun install
```

That also installs the commit hook, which rejects a message that is not a
[conventional commit](AGENTS.md#commits) or that holds an absolute local path.

## Run the gates

```bash
bun run typecheck && bun run lint && bun run test
```

Before a release, also `bun run test:cli`, `bun run test:integration`,
`bun run package` and `bun run test:e2e-vsix`. What each covers is under
Toolchain and "Verified in a real editor" in AGENTS.md.

## Make a change

- **Branch off `main`.** `main` takes pull requests only. The pull request
  template lists what a reviewer would otherwise ask for first.
- **A new rule ships with three tests** and a pair of examples in
  `fixtures/rule-examples.json`, and its page is generated by
  `bun run docs:rules`, never edited. The rule is under Invariants in
  AGENTS.md, as is every other rule that governs a change to a rule, a
  reader, a fix or a check.
- **The corpus is in our own words.** Never copy a question from another
  project or from vendor docs into `fixtures/corpus/`. Label an example
  before any rule runs over it, regenerate `scores.json` with
  `bunx vitest run src/lint/corpus.test.ts -u`, and read the diff.
- **A reader or rule change is run over public code before it is trusted.**
  Three rounds of that found more wrong with the rules than every test in the
  repository. `scripts/fetch-public-code.ts` draws the files. Say in the
  pull request what the run found.
- **A change to a model-backed check or a cutoff** regenerates
  `docs/cutoffs.md` with `bun run docs:cutoffs`. The scripts that send to a
  platform are run by hand, each with `--dry-run` and a call limit; no test
  reaches the network.
- **Keep AGENTS.md current** in the same change that alters what it
  documents.

## Report something

Use the issue forms. A finding that was wrong and a question that was missed
each have their own, and ask for the three things such a report needs: the
question as written, the language it was written in, and the rule code. For
a security problem, see [SECURITY.md](SECURITY.md).
