# Two wire shapes rule decision-model APIs

As of 2026-10-14, every typed decision-model API found speaks one of two wire shapes. The first is TypeSafe's System One: `POST /v1/systemone` with a `state` and a `questions` map keyed by id, types `noul`, `choice` and `score`, and a `criteria` field. The second is OpenAI's Decisions: `POST /v1/decisions` with `model`, `input` and a `questions` array, types `predicate`, `choice` and `score`, and `choices` or `levels` lists. A third vocabulary, `boolean`, lives in the Vercel AI SDK and Vercel's native endpoint. **System One is the de facto standard.** Microsoft, Liquid AI, Cloudflare, Upstage, Nace.AI, llama.cpp, vLLM and dozens of open reimplementations adopted it. OpenAI's shape is spreading through gateways (Vercel, LiteLLM, LLM Gateway, OpenRouter), which serve both shapes and translate between them, so the same model id can arrive in either body. **"Open Jev" is not one product.** It is a name used by at least nine unaffiliated projects that reimplement `/v1/systemone`. **No decision model, vendor or API named "JAY" exists in any source searched.** For JevLint-LE this means the body shape, not the URL or the model id, must decide the dialect. Limits must be looked up per target, because many are unpublished and OpenAI states none. Model ids come in at least fifteen spellings for two underlying models. The call shapes worth adding are the OpenAI SDKs' `decisions.create`, TypeSafe's `system_one` / `systemOne`, the AI SDK's `experimental_decide` and its legacy `experimental_evaluate`, and LangChain's `TypeSafeClassifier`. On evidence: OpenAI, Liquid, Vercel, the AI SDK, LiteLLM, LLM Gateway, OpenRouter, Eden AI, LangChain and llama.cpp were read from their own docs. TypeSafe's field-level reference was not fetched in this round, but the repo's `src/lint/limits.ts` quotes it as read on 2026-10-04. Microsoft, Cloudflare, Perplexity, Upstage and every small vendor rest on secondary coverage.

Evidence labels used below: **P** means the vendor's or project's own page was fetched. **S** means secondary coverage (news, aggregators, surveys). **S1** means a single secondary source with nothing corroborating it.

## TypeSafe and OpenAI define the two reference shapes

TypeSafe launched Jev on 2026-09-15 as the first "System One" model ([DataCamp](https://www.datacamp.com/blog/system-one-models-jev)). It is closed-weight and hosted only ([llmconfigurator](https://llmconfigurator.com/en/guides/decision-models/open-models-beyond-ollama)). The endpoint is `POST https://api.typesafe.ai/v1/systemone`, the official SDKs are `typesafe-sdk` (Python) and `@typesafe-ai/sdk` (TypeScript), and the floating alias is `jev-latest` ([MarkTechPost](https://www.marktechpost.com/2026/09/19/typesafe-ai-releases-jev/), S). The repo's own limits file records what TypeSafe's reference said on 2026-10-04 (P): **a maximum of 255 options per Choice** ([docs.typesafe.ai/api#choice](https://docs.typesafe.ai/api)), **Score takes 2 to 10 levels** ([docs.typesafe.ai/api#score](https://docs.typesafe.ai/api)), Noul's only documented criteria keys are `true` and `false` ([docs.typesafe.ai/api#noul](https://docs.typesafe.ai/api)), the aliases are `jev-latest` and `jev-preview`, and both pointed at `jev-1.13.0` ([docs.typesafe.ai/models](https://docs.typesafe.ai/models)). Those values settle a conflict in the secondary literature, where one survey claims Jev's Score runs 0 to 5 ([redreamality](https://redreamality.com/blog/open-decision-models-2026-survey-benchmarks/)). Context length is **genuinely disputed**. OpenRouter's guide says 32,000 tokens counting `state` plus questions ([OpenRouter](https://openrouter.ai/docs/guides/community/jev), P for OpenRouter's surface), and so does [explainx](https://explainx.ai/blog/top-10-decision-models-jev-perplexity-openai-open-source-ranked-2026). Other aggregators say 64K ([systemonemodels.org](https://systemonemodels.org/models/), S). Pricing is reported at $0.042 per 1M input tokens with free output (S). Whether the API still has a waitlist is also unclear. jevmodel.org says it opened on 21 Sep 2026, but that site is not clearly TypeSafe's ([jevmodel.org](https://jevmodel.org/), S1).

OpenAI's Decisions API is the only other reference shape, and every fact about it comes from its own guide (P) ([OpenAI guide](https://developers.openai.com/api/docs/guides/decisions)). It serves `POST /v1/decisions` with **one model, `gpt-6-luna`, and no aliases or snapshots**. It is in public beta with GA "in the coming weeks". The request carries `model`, `input` and `questions`. The `input` field takes a string or messages with `input_text` / `input_image` parts. A `predicate` question has `type`, `name` and `instructions` and returns `probability`. A `choice` adds `choices[{value, description}]` and returns `choice`, `probabilities[{value, probability}]` and `confidence`. A `score` adds `levels[{label, description}]`, indexed from 0, and returns `score`, `probabilities[{value, label, probability}]` and `confidence`. Names must be unique, answers come back as an ordered `answers` array, and a **`refusal` answer type** exists that System One lacks. **The guide states no limit on choices, levels, questions or input length.** Images must be inline base64 data URLs, and hosted URLs and `file_id` are refused. Pricing is $0.10 per 1M input tokens with free output. The minimum SDKs are Python 3.26.0, JavaScript 7.30.0, Go 3.73.0, Ruby 0.101.0 and Java 4.78.0. The public beta opened on 2026-10-06 ([Unite.AI](https://www.unite.ai/openai-releases-decisions-api-in-public-beta-powered-by-gpt-6-luna/), S). The limits OpenAI omits show up only at gateways. Vercel's OpenAI-compatible path documents **1 to 255 `choices`, 2 to 10 `levels`, an optional `name` (returning `name: null`), no `true` beside `"true"` among choice values, and at most 128 images** ([Vercel](https://vercel.com/docs/ai-gateway/sdks-and-apis/openai-decisions.md), P for Vercel). LLM Gateway quotes a 1.05M context with a higher rate above 272K input tokens ([LLM Gateway changelog](https://llmgateway.io/changelog/openai-compatible-decisions-api)).

The two shapes map almost field for field. `noul` becomes `predicate`, a `criteria` map becomes `choices[{value, description}]`, a `criteria` list becomes `levels[{label, description}]`, `state` becomes `input`, and the map key becomes `name`. This mapping is inferred from the OpenAI guide and Liquid's docs. Gateways that translate both ways show it works, but no vendor has published it field by field.

## Most other hosted vendors copied System One

Microsoft, the one major cloud with its own model, skipped OpenAI's shape ([The New Stack](https://thenewstack.io/microsoft-decision-model-foundry/)). Microsoft-Decision-1 serves `<Foundry resource>/providers/microsoft/v1/systemone` with types `noul`, `choice` and `score`, 32K tokens of text or JSON input, and a `model` field that takes **your deployment name**. The `model` in the response can differ from what you sent. It is a post-trained Qwen3.5-9B priced at $0.042 per 1M input ([logeshwaran.org](https://www.logeshwaran.org/2026/10/microsoft-decision-1-model-foundry.html), S). Microsoft's own doc returned 404, so every per-question limit is unverified. Sources also disagree on whether it is in preview or GA, and on whether it opened on 2026-10-08 or 10-09 ([testingcatalog](https://www.testingcatalog.com/microsoft-launches-decision-1-model-in-foundry/), [orcarouter](https://www.orcarouter.ai/blog/microsoft-decision-1-ga-foundry-no-published-benchmarks)). Azure lists `gpt-6-luna` in its Foundry catalog, but no Azure `/decisions` route was found ([Azure catalog](https://ai.azure.com/catalog/models/gpt-6-luna)).

Liquid AI's d1 is the best-documented System One clone (P) ([Liquid docs](https://docs.liquid.ai/lfm/models/d1)). It serves `POST https://api.liquid.ai/decisions/v1/systemone` with `liquid_`-prefixed Bearer keys. The model ids are `d1`, which is paid and accepts images, and `d1:free`, which is text only. The body has `model`, `state`, `questions` keyed by name, and optional `images`. A `noul` takes `instructions`, a `choice` takes a `criteria` map, and a `score` takes `criteria` as an ordered list and returns a `legend`. **Liquid's official clients are TypeSafe's own SDKs.** It allows up to 8 images and a body under 4.5 MB, and states no option, level, question or context limit. Cloudflare's Clef family runs on Workers AI as `@cf/cloudflare/clef` and `@cf/cloudflare/clef-flash`, plus Clef-omni for image, audio and video. It is reported as Jev-compatible, called at the account's `/ai/run/@cf/cloudflare/clef` path, with **up to 64 questions per request, 2 to 255 options, up to 4 images, and 64K context** (24K for flash) ([flaviocopes](https://flaviocopes.com/clef/), [xenospectrum](https://xenospectrum.com/en/cloudflare-clef-decision-models/), [Developers Digest](https://www.developersdigest.tech/blog/cloudflare-clef-decision-models-2026), all S). Upstage's Solar Decide and Solar Decide Flash use System One at `/v1/systemone`, and the schema "may change before GA" ([llmreference](https://www.llmreference.com/provider/upstage/solar-decide), S). A headline says AWS, Upstage and Ollama agreed on a common decision-model API that OpenAI has not joined, but the article body could not be retrieved ([The New Stack](https://thenewstack.io/decision-models-system-one/), S1).

Perplexity is the one hosted vendor reported on OpenAI's path. pplx-decider is said to serve `POST https://api.perplexity.ai/v1/decisions` with **up to 128 named questions** and under 262,144 input tokens. That claim comes from one aggregator and was not checked against Perplexity's docs ([llmreference](https://www.llmreference.com/provider/perplexity-api/pplx-decider-v1-27b), S1). Its ids are `pplx-decider-v1-27b` and `pplx-decider-v1.1-27b`, and OpenRouter lists `perplexity/pplx-decider-v1.1-27b-20261006` ([OpenRouter](https://openrouter.ai/perplexity/pplx-decider-v1.1-27b-20261006)). A long tail of small vendors appears only on one aggregator ([systemonemodels.org](https://systemonemodels.org/models/), S1): Celeris, Fastino GLiDE, Inception Mercury Decide, Hanzo Kai 1, Nace.AI Drex 1.5, Respan Span-01 (Noul only), Together AI Tev1-4B-experimental (choice only, 2 to 24 options) and meraGPT Decider 1. Their contexts run from 1,024 tokens to about 136K. Superagent's Security-One 27B returns unsafe probabilities, which puts it at the guardrail edge of the category. Supersonic Labs' Julia 1 caps choices at 20 ([explainx](https://explainx.ai/blog/top-10-decision-models-jev-perplexity-openai-open-source-ranked-2026), S). No decision endpoint was found from Anthropic, Google, Mistral, Cohere, xAI, Meta, DeepSeek, AI21, Databricks or Amazon Bedrock. That conclusion rests on aggregator listings and searches, not on each vendor's changelog. Amazon's entry, Strands-Decider 2B, is open-weight and runs on a local `/v1/systemone` ([logeshwaran.org](https://www.logeshwaran.org/2026/10/microsoft-decision-1-model-foundry.html), S).

## Gateways serve both shapes and rename every model

The gateways are where the two shapes meet, and they are the best-documented layer (all P). **Vercel AI Gateway runs three surfaces.** The native `POST https://ai-gateway.vercel.sh/v1/evaluate` takes the AI SDK shape with type `boolean`. An OpenAI-compatible `POST /v1/decisions` sits at base URL `https://ai-gateway.vercel.sh/v1`. A TypeSafe-compatible base sits at `https://ai-gateway.vercel.sh/typesafe` and accepts `noul` ([Vercel: Decision](https://vercel.com/docs/ai-gateway/modalities/decision.md), [Vercel: OpenAI-compatible](https://vercel.com/docs/ai-gateway/sdks-and-apis/openai-decisions.md)). Vercel's ids are `typesafe-ai/jev` and **`openai/gpt-6-luna-decisions`, not `openai/gpt-6-luna`**. Its fallback option can name a plain language model that answers through structured output. One Vercel explainer says the OpenAI-compatible path rejects images ([Vercel explainer](https://vercel.com/i/what-is-openai-decisions-api), S). Vercel's own docs page instead allows up to 128 base64 images. **The docs page is the stronger source**, and the conflict is unresolved.

LiteLLM v1.104.2 serves `/v1/decisions` and `/decisions` in OpenAI's shape and `/v1/systemone` and `/systemone` in TypeSafe's, over one internal format ([LiteLLM release notes](https://docs.litellm.ai/release_notes/v1.104.2/v1-104-2.md)). It returns a 400 before any upstream call for a missing `state`, a malformed question, **more than 128 questions, or a single-option question**. That last check contradicts Vercel's floor of one `choices` entry. LiteLLM's ids are provider-prefixed: `openai/gpt-6-luna`, `perplexity/pplx-decider-v1-27b`, `cloudflare/clef`, `cloudflare/@cf/cloudflare/clef` and `strands_decider/strands-decider-2B-hobson-v19`. OpenRouter serves `/api/v1/systemone`, which a TypeSafe SDK reaches by setting the base URL to `https://openrouter.ai/api`, and `/api/alpha/decisions`. It maps `jev-1.13` to `typesafe/jev-1.13` and `jev-latest` to the tilde alias `~typesafe/jev-latest`, reports `typesafe/jev-1.13-20260917` in responses, and adds `id`, `provider` and `usage.cost` ([OpenRouter TypeSafe SDK guide](https://openrouter.ai/docs/guides/community/typesafe-sdk.md), [OpenRouter Jev guide](https://openrouter.ai/docs/guides/community/jev)). It also lists `openai/gpt-6-luna-decisions` and the snapshot `openai/gpt-6-luna-decisions-20261006`, reportedly with up to 200 questions per request. That figure was seen only in a search snippet ([OpenRouter](https://openrouter.ai/openai/gpt-6-luna-decisions), S1).

LLM Gateway serves `POST https://api.llmgateway.io/v1/decisions` with **unprefixed ids** (`gpt-6-luna-decisions`, `microsoft-decision-1`, `jev-1.13.0`). It translates to TypeSafe's shape behind the scenes and marks its `/v1/systemone` "Deprecated soon" ([LLM Gateway: Decisions](https://docs.llmgateway.io/features/decisions), [LLM Gateway: System One](https://docs.llmgateway.io/features/system-one)). Eden AI keeps TypeSafe's bodies on a path of its own, `POST /v3/alpha/decisions`, so a base-URL swap does not reach it. Its ids are `typesafe/jev-latest` and `typesafe/jev-preview`, with up to 255 options, and an empty Score rubric returns a 422 ([Eden AI](https://www.edenai.co/docs/v3/llms/decisions)). Haimaker serves Solar Decide at `api.haimaker.ai/v1/decisions` with predicate, choice and score ([Haimaker](https://haimaker.ai/models/upstage/solar-decide), S1). **No evidence was found** that Together, Fireworks, Groq, Portkey, Bedrock, Vertex or Hugging Face Inference Providers proxy either shape.

## Open Jev is a family of local servers, and JAY does not exist

"Open Jev" names at least nine independent projects, and none of them is TypeSafe's. TypeSafe's docs never mention any of them ([docs.typesafe.ai](https://docs.typesafe.ai), P). Every project that documents an HTTP interface targets `/v1/systemone`. **None targets `/v1/decisions`.** They deviate from Jev in field names and limits. GPT-AGI/OpenJev, the repo that calls itself "Opensource Jev" and ranks first in search, is at "Phase 0" with 21 stars and no weights. Its server is not shipped, and it renames the fields to `options` and `legend` in place of `criteria` ([GitHub](https://github.com/GPT-AGI/OpenJev), P). Zefan-Cai/Open-Jev ships LoRA checkpoints (`ZefanCai/Open-Jev-2B`, `-9B`, `-27B-v1.1`). Its server is `python -m jev.server` on port 8791 with `--max-length 4096`, and score `criteria` is a list of strings ([wiki](https://github.com/Zefan-Cai/Open-Jev/wiki), P). alanhuangya/OpenJev-8B is a "drop-in POST /v1/systemone" served by `wev serve` on port 8009. It accepts up to 4,096 state tokens and 8,192 per question, and was never tested against real Jev ([HF](https://huggingface.co/alanhuangya/OpenJev-8B), P). shenjunhao/OpenJev-4B uses the same field names but documents no HTTP path ([HF](https://huggingface.co/shenjunhao/OpenJev-4B), P). The four others are known only from a curated list: razorback16/openjev (patched vLLM), daseinlabs/open-jev (MLX), zhihz/openjev and Algorythm-Canada/OpenJevSwift ([awesome-jev](https://github.com/cobanov/awesome-jev), S). **No project publishes a JSON schema, an auth scheme or an error shape.**

The most consequential Open Jev is the one shipped by a runtime. llama.cpp gained a native `/v1/systemone` on 2026-10-02 that "existing clients only need a new base URL" to use. It serves `ggml-org/OpenJev-GGUF`, a 27B CC BY-NC 4.0 model whose upstream author is unnamed ([HF blog](https://huggingface.co/blog/ggml-org/decision-models-in-llamacpp), P). The llama.cpp endpoint adds an optional `images` field and an optional `model` field for router mode, allows `state` to be a list of chat messages, and requires Score criteria to be an array of 2 to 10 levels, lowest first. vLLM reportedly merged a generic `/v1/systemone` on 2026-10-08, while PRs for OpenAI's schema stayed open ([redreamality](https://redreamality.com/blog/open-decision-models-2026-survey-benchmarks/), S1, PR not located). Ollaya, an independent Apache-2.0 runtime on port 11435, serves `/v1/systemone` and **`/v1/decisions`, both described as TypeSafe wire-identical**. Its model names are Ollama-style tags such as `laya`, `kev:9b`, `clef` and `d1` ([Ollaya wiki](https://github.com/ollaya-dev/ollaya/wiki), P). A minority of servers use `/v1/decide` instead. Those are AnyJev, which wraps Ollama or vLLM backends, and AutoTrust's `autotrust/JEV-9B` and `JEV-27B-VL`, which are distilled from Jev 1.13's outputs ([redreamality](https://redreamality.com/blog/open-decision-models-2026-survey-benchmarks/), S). Open weights also exist for Clef, Clef-flash, Liquid d1-3B and d1-omni-600M, pplx-decider, H2O-Lightning-4B, Laya, CLM-v0.1-8B, Strands Decider and Julia-1 (same survey, S).

Seven targeted searches for "JAY", "Jay" and "J.A.Y." returned no decision model, vendor or API. The word appears on none of the ten primary pages listed in the JAY research note. The nearest names are Jev itself, AutoTrust's "JEV" models, Jebadiah (`getainode/jebadiah`, Apache-2.0 models on Jev's wire format) ([awesome-jev](https://github.com/cobanov/awesome-jev)) and Julia-1. **JAY should not be built for until someone supplies a URL or a model id.**

## Five client families define the call shapes in source code

The OpenAI SDKs give the most call shapes, all from the guide (P) ([OpenAI guide](https://developers.openai.com/api/docs/guides/decisions)). They are Python `client.decisions.create(model=, input=, questions=)`, JavaScript `client.decisions.create({model, input, questions})`, Go `client.Decisions.New(ctx, openai.DecisionNewParams{...})`, Java `client.decisions().create(DecisionCreateParams.builder()...)` and Ruby `client.decisions.create(model:, input:, questions:)`. The Go question struct's field names were not retrieved. The same calls reach Vercel and LLM Gateway with only a base-URL change ([Vercel](https://vercel.com/docs/ai-gateway/sdks-and-apis/openai-decisions.md), [LLM Gateway](https://docs.llmgateway.io/features/decisions)). The TypeSafe SDKs call `client.systemOne({ model, state, questions })` in TypeScript and `client.system_one(model=..., state=..., questions={...})` in Python. Both read `TYPESAFE_API_KEY` and `TYPESAFE_BASE_URL`, and the base-URL variable is how Liquid, OpenRouter, Vercel's `/typesafe` and Ollaya are all reached ([OpenRouter TypeSafe SDK guide](https://openrouter.ai/docs/guides/community/typesafe-sdk.md)). Unofficial clients exist for Go (`github.com/nibir1/typesafe-go`), Rust (`typesafe-rs`, `kunobi-jev`) and PHP (`doekos/typesafe-laravel-sdk`), but only their constructors were seen ([pkg.go.dev](https://pkg.go.dev/github.com/nibir1/typesafe-go), [docs.rs](https://docs.rs/typesafe-rs)).

The Vercel AI SDK uses `import { experimental_decide as decide } from 'ai'` with `{ model, state, questions }`. It requires `ai` 7.0.128 or later, and earlier 7.x releases used the name `experimental_evaluate`, which survives as a deprecated alias ([Vercel: Decision](https://vercel.com/docs/ai-gateway/modalities/decision.md)). Its types are `boolean` (optional `criteria: { true, false }`), `choice` (a non-empty criteria map) and `score` (an array of at least two labels). Models come from factories: `typeSafeAi.decisionModel('jev-latest')`, `openai.decisionModel('gpt-6-luna')`, `gateway.decisionModel('typesafe-ai/jev')`, and **`anthropic.decisionModel(...)` and `google.decisionModel(...)`, which answer with ordinary language models** ([AI SDK docs](https://ai-sdk.dev/docs/ai-sdk-core/decisions)). LangChain's `langchain-typesafe` wraps questions in constructors: `TypeSafeClassifier().invoke({"state": ..., "questions": {"id": Noul(instructions=...) | Choice(instructions=..., criteria={...}) | Score(instructions=..., criteria=[...])}})`, with `NoulCriteria(true=, false=)`. Older releases set `questions` on the constructor ([LangChain](https://docs.langchain.com/oss/python/integrations/providers/typesafe.md)). No decision primitive was found in DSPy, Instructor, Pydantic AI, Mastra, Spring AI, Semantic Kernel or LlamaIndex, from one combined search. The LiteLLM Python SDK documents no decision function.

## What JevLint-LE needs to read every surface

**The body shape decides the dialect, never the path or the model id.** `state` with a `questions` object is System One, and `input` with a `questions` array is OpenAI. The path is ambiguous: Ollaya serves TypeSafe bodies on `/v1/decisions`, and Eden AI serves them on `/v3/alpha/decisions`. The model id is ambiguous too. `typesafe-ai/jev` answers on Vercel's OpenAI-shaped path, and `openai/gpt-6-luna` answers on LiteLLM's `/v1/systemone`. The repo's existing rule that "a question carries its dialect" already fits this. What it lacks is a few variants. The yes/no type has three wire names (`noul`, `predicate`, `boolean`), plus LangChain's `Noul` class. Score criteria arrive as a TypeSafe list, as OpenAI `levels`, and as GPT-AGI's `legend`. `options` and `legend` belong to an unshipped Phase-0 project, so adding them is optional and low value. The OpenAI dialect's optional `name` and its `refusal` answer type have no System One counterpart. Vercel's rule against mixing `true` and `"true"` among choice values is a new check that only that dialect needs.

**Limits must be keyed by target, with Jev's as the default.** Jev's 255 options and 2 to 10 levels match Vercel, Eden AI, Clef and llama.cpp, which makes them a safe common rule. The values that differ are questions per request (32 on Laya's hosted offering, 64 on Clef, 128 on LiteLLM and Perplexity, a reported 200 on OpenRouter for Luna), the minimum number of choices (1 on Vercel, 2 on LiteLLM), choice caps on small models (24 for Tev1, 20 for Julia 1), and images (4 on Clef, 8 on Liquid, 128 on Vercel, base64 only on OpenAI). Context runs from 1K to 1.05M. **OpenAI publishes no limits for `gpt-6-luna`.** Under the repo's rule that no vendor number lives outside `src/lint/limits.ts` with its source, a limit rule should stay silent for the OpenAI dialect rather than borrow Vercel's numbers. The only exception would be a request whose target is known to be Vercel. Every S1 number in the inventory is unfit for `limits.ts` until it is read from the vendor.

**Model-id handling must accept many spellings of the same model.** The Jev family appears as `jev-1.13.0`, `jev-1.13`, `jev-latest`, `jev-preview`, `typesafe/jev-*`, `~typesafe/jev-latest`, `typesafe-ai/jev` and the response-only `typesafe/jev-1.13-20260917`. Luna appears as `gpt-6-luna`, `openai/gpt-6-luna`, `gpt-6-luna-decisions`, `openai/gpt-6-luna-decisions` and `openai/gpt-6-luna-decisions-20261006`. Several alias schemes coexist: floating aliases, OpenRouter's tilde, dated snapshots, tier suffixes (`d1:free`), Azure deployment names, `@cf/` paths, Ollama tags and Hugging Face repo ids. Two consequences follow. A pin rule must treat `~typesafe/jev-latest` and `typesafe/jev-latest` as floating aliases and must not demand `jev-*` from a self-hosted endpoint. More important, `jev/provider.ts` picks one of two hosts from the model id. A gateway id such as `openai/gpt-6-luna-decisions` or `typesafe-ai/jev` must be refused rather than routed to `api.openai.com` or `api.typesafe.ai`. Sending it would spend the user's key on a request that fails.

**The call shapes worth adding are few and well documented.** In JS/TS, they are `*.decisions.create({...})`, `*.systemOne({...})`, and `experimental_decide` / `experimental_evaluate`. The AI SDK import is conventionally aliased (`as decide`), which collides with the known limitation that aliased imports are not followed. In Python, they are `*.decisions.create(...)` with keyword arguments, `*.system_one(...)`, and LangChain's `Noul` / `Choice` / `Score` constructors. Those LangChain classes are imported from `langchain_typesafe`, not `typesafe_sdk`, so the rule that a class counts as a question only when imported from `typesafe_sdk` needs that module added, after a run over public code. In Go, the form is `client.Decisions.New(ctx, openai.DecisionNewParams{...})`, but its question struct fields are unknown and need reading from the SDK first. Java and Ruby fall outside the current language set. One caution applies to every AI SDK call: it may be answered by an Anthropic or Google language model, or by a gateway fallback. A question that lints as "for Jev" there is not necessarily answered by Jev.

## Conclusion

The category is four weeks old and has already split along a clean seam. Model makers and local runtimes converged on TypeSafe's body, while the gateways that sit between applications and models are moving toward OpenAI's body as the client-facing one. LLM Gateway is already deprecating System One. A linter keyed to vendors would chase a new model every week. One keyed to two body shapes and one client vocabulary covers nearly every surface found, because the long tail of vendors differs in limits and ids, not in field names. The open risks are the unverified claims: Perplexity's path, Microsoft's per-question limits, Cloudflare's REST shape and the vLLM merge. The table marks each one, and each needs a primary read before it reaches `limits.ts`. Microsoft, Liquid and Cloudflare copied Jev's shape, so the existing System One rules already cover them once the model id is no longer used to pick the dialect.
